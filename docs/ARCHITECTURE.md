# Локальная ассистентка — архитектура

Обновлено: 17.10.2026 · Живая версия документа: https://claude.ai/code/artifact/064ccc08-8f2c-443f-9a94-24ed1988e68c

## Цели и принципы

Цель: голосовая ассистентка на Galaxy S25, которая работает без интернета. Она ведёт рабочие проекты, отвечает по лифтовой документации, помнит разговоры месяцами и при появлении сети передаёт задачи облачному агенту.

Что она умеет:

- Голосовой диалог с задержкой до первого слова 1–2 секунды.
- Рабочий режим: ответы по инструкциям и схемам, заметки, задачи, отчёты по объектам.
- Долговременная память: разговоры раскладываются по проектам и темам.
- Характер и эмоции: настроение меняется день ото дня и реагирует на то, как с ней общаются.
- Приватный режим без цензуры, полностью локальный.
- Облачный шлюз: она готовит задачи для Claude, а его ответы пересказывает голосом.

Принципы, которые не нарушаем:

1. **Offline-first.** Всё основное работает без сети. Облако только добавляет возможности.
2. **Каждый движок за интерфейсом.** Распознавание речи, модель, синтез и эмбеддинги заменяются одной строкой в конфиге. Модели устаревают каждые полгода.
3. **Персонаж — это данные, а не код.** Характер, голос, гардероб и промпты лежат в YAML-файлах.
4. **Приватное не покидает телефон.** Записи приватного режима помечены и жёстко отфильтрованы от облачного шлюза.
5. **Модули общаются через события.** Голос, мозг и аватар не знают друг о друге напрямую, поэтому любой можно переписать отдельно.
6. **Решения записываются.** Каждое важное архитектурное решение — короткий файл в `docs/adr/`.
7. **Качество проверяется тестовыми диалогами.** При смене модели прогоняем набор эталонных вопросов и сравниваем ответы.

**Без подписок.** Все модели, голоса и библиотеки бесплатные, с открытыми лицензиями, и хранятся на телефоне. Допустимы только разовые покупки, например 3D-модель или набор анимаций. Единственная плата по факту — облачный агент Claude, и только когда им пользуешься. Своего сервера с ежемесячной арендой нет: телефон обращается к Claude API напрямую.

## Общая схема

Приложение — одно Android-приложение на Kotlin. Unity встроен в него как библиотека (Unity as a Library) и отвечает только за картинку. Вся логика, память и модели живут в Kotlin-ядре и нативных библиотеках на C++.

```
┌──────────────────────────────────────────────────────────────┐
│ Аватар · Unity — VRM, анимации, мимика, губы, сцены, гардероб │
└──────────────────────────────┬───────────────────────────────┘
┌──────────────────────────────┴───────────────────────────────┐
│ Шина событий: реплики, эмоции, анимации, смена режима         │
└──────┬───────────────────────┬───────────────────────┬───────┘
┌──────┴──────────┐  ┌─────────┴─────────┐  ┌──────────┴────────┐
│ Голосовой       │  │ Оркестратор       │  │ Персонаж и эмоции │
│ конвейер        │  │ диалога           │  │ режимы работа/    │
│ VAD→STT→TTS     │  │ промпт, команды   │  │ приват            │
└──────┬──────────┘  └─────────┬─────────┘  └───────────────────┘
┌──────┴───────────────────────┴───────────────────────────────┐
│ Движки (заменяются через конфиг):                             │
│ llama.cpp · whisper.cpp · Silero/Piper · ONNX (эмбеддинги)    │
└──────┬───────────────────────────────────────┬───────────────┘
┌──────┴──────────────────────┐  ┌─────────────┴───────────────┐
│ Память и проекты            │  │ База знаний по лифтам       │
│ SQLite + векторный поиск    │  │ пакеты из tools/ingest      │
└──────┬──────────────────────┘  └─────────────────────────────┘
┌ ─ ─ ─┴─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
  Облачный шлюз → Claude API (только при сети, без приватного)
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

Верхние слои ничего не знают о нижних: аватар получает события «говорю», «эмоция: смущение», «анимация: танец» и просто их показывает. Поэтому Unity можно заменить, а модель — обновить, не трогая остальное.

## Модули

Девять модулей, у каждого одна зона ответственности и свой интерфейс.

### 1. Голосовой конвейер

Цепочка: микрофон → детектор речи (Silero VAD) → распознавание (whisper.cpp) → оркестратор → разбивка ответа на предложения → синтез (Silero TTS) → динамик и движение губ.

- Ответ озвучивается по предложениям, пока модель дописывает остальное.
- Перебивание: если ты заговорил, она замолкает и слушает.
- Слово-активатор («Алло, [имя]») — опционально, на этапе 2.
- Синтез отдаёт аватару не только звук, но и фонемы для губ.

### 2. Оркестратор диалога

Мозг приложения. На каждую реплику собирает промпт из частей:

1. Карточка персонажа и правила текущего режима.
2. Текущее эмоциональное состояние.
3. Подходящие воспоминания и факты о проектах.
4. Фрагменты документации, если вопрос рабочий.
5. Последние 10–20 реплик.

Модель отвечает текстом и, при необходимости, командами в JSON: `save_note`, `create_task`, `search_docs`, `play_animation`, `send_to_cloud`. Формат JSON жёстко задаётся грамматикой llama.cpp (GBNF), поэтому маленькая модель не может выдать сломанную команду.

### 3. Персонаж и эмоции

Характер, манера речи, голос, гардероб и запреты описаны в `persona/*.yaml`. Эмоции — два уровня:

- **Настроение дня.** Медленное, меняется раз в сутки. Задаётся случайно с инерцией и событиями: ты пропал на три дня — она немного обижена; закрыли сложный объект — довольна.
- **Сиюминутная эмоция.** Быстрая реакция на реплику: радость, смущение, раздражение, грусть. После каждого ответа модель коротко оценивает, как изменилось состояние.

Состояние влияет на три вещи: формулировки (через промпт), голос (скорость и интонация синтеза) и лицо аватара (мимика). Состояние хранится в базе, поэтому завтра она помнит, что вчера обиделась.

### 4. Память

Четыре уровня, как у человека:

| Уровень | Что хранит | Срок |
| --- | --- | --- |
| Рабочая | Последние реплики текущего разговора | Один разговор |
| Эпизоды | Краткие сводки каждого разговора с датой | Всегда |
| Факты | О тебе, людях, объектах: «на объекте в Холоне лифт Schindler» | Всегда, обновляются |
| Проекты | Темы, задачи, заметки, статусы | Пока проект жив |

**«Сон».** Когда телефон заряжается ночью, запускается фоновая обработка: сводки дня, извлечение фактов, раскладка по проектам, слияние дублей. Днём модель занята разговором, а тяжёлая работа делается ночью.

Поиск по памяти сочетает смысловое сходство (эмбеддинги) и свежесть записи.

### 5. Проекты и задачи

Каждый разговор привязывается к проекту: она сама предлагает «это про объект в Бат-Яме?» и создаёт новый, если тема новая. У задачи есть статус, срок и исполнитель: ты, она или облачный агент. Позже проекты синхронизируются с Lift PM.

### 6. База знаний (лифты)

Документы готовятся на компьютере утилитой `tools/ingest`:

1. PDF разбирается на текст.
2. Схемы и сканы описываются текстом через Claude: клеммы, цепи, коды ошибок. Это разовая работа, потом всё работает офлайн.
3. Текст режется на куски и индексируется.
4. Результат — файл-пакет (например, `schindler-3300.kpack`), который копируется на телефон.

Ответ на рабочий вопрос всегда со ссылкой: «по инструкции, раздел 4.2, страница 37».

### 7. Режимы

- **Работа** и **приват**: разные промпты, сцены и гардероб; модель одна.
- Переключение по расписанию, голосом или кнопкой.
- Приватный режим включается ключевой фразой и подтверждением «да» после нейтрального переспроса (ADR 0009). Без отпечатков и PIN.
- Жест «паника» мгновенно возвращает рабочий режим.
- Каждая запись в памяти помечена областью (`work` или `private`). В рабочем режиме приватные записи не попадают в поиск.

### 8. Облачный шлюз

Она формулирует задачу для Claude: «найди, есть ли новая прошивка контроллера X», «предложи, как организовать график монтажей». Задачи копятся в очереди и уходят, когда появляется сеть. Ответ приходит, сохраняется в проект, и она пересказывает его голосом своими словами.

- Телефон обращается к Claude API напрямую, свой сервер не нужен.
- Оплата только за реальные запросы, без подписки.
- Жёсткий фильтр: записи с областью `private` в шлюз не попадают никогда.
- Ключ API хранится в защищённом хранилище Android (Keystore).

### 9. Аватар (Unity)

- Персонаж в формате VRM: свой, сделанный в VRoid Studio, или купленный разово.
- Конечный автомат анимаций: ожидание, разговор, жесты, позы и танцы по командам.
- Мимика из эмоционального состояния, движение губ по фонемам из синтеза.
- Сцены и наборы одежды по режимам.
- Unity получает команды через шину и ничего не решает сам.

## Модели и ресурсы

Всё в стартовом наборе бесплатно и работает без сети. Цифры примерные, по памяти, без проверки на S25 — замерим на этапе 4.

| Задача | Стартовый выбор | Размер, примерно | Лицензия |
| --- | --- | --- | --- |
| Языковая модель, все режимы | Одна модель без цензуры: uncensored-версия Qwen3 (4B или 8B) или Gemma 3 4B, Q4 | 2.5–5 ГБ | как у исходной модели |
| Распознавание речи | Whisper small (whisper.cpp) | 0.5 ГБ | MIT |
| Детектор речи | Silero VAD | 2 МБ | MIT |
| Синтез речи | Silero TTS (русский), запасной — Piper | 0.1 ГБ | Silero: только некоммерческое, для личного проекта подходит |
| Эмбеддинги | multilingual-e5-small | 0.12 ГБ | MIT |
| 3D-движок | Unity Personal | — | бесплатно для личного использования |
| Персонаж | VRoid Studio или разовая покупка | — | бесплатно / разово |

**Бюджет памяти S25 (12 ГБ).** Android и фоновые приложения занимают 4–5 ГБ. Одновременно держим одну языковую модель (около 3 ГБ с контекстом), Whisper (0.5), синтез и эмбеддинги (0.3), Unity-сцену (около 1 ГБ). Итого около 5 ГБ — помещается с запасом. Языковая модель одна на все режимы, поэтому смена режима мгновенная — меняется только промпт (ADR 0007).

**Место на диске:** около 7–8 ГБ на модели плюс пакеты документации.

## Структура репозитория

Один приватный репозиторий (монорепо): все части меняются вместе, и мне проще видеть картину целиком.

```
/docs
    ARCHITECTURE.md      этот документ
    adr/                 архитектурные решения, по файлу на решение
/prototype               прототип на Python для Mac: голос, память, эмоции
/android                 приложение на Kotlin
    core/                шина событий, оркестратор, режимы
    voice/               голосовой конвейер
    memory/              память, проекты, база (Room + sqlite-vec)
    persona/             эмоции и загрузка персонажа
    cloud/               очередь и клиент Claude API
/native                  C++: llama.cpp и whisper.cpp как подмодули + JNI-обёртки
/unity                   проект аватара
/persona                 карточки персонажа, промпты, голоса (YAML)
/tools/ingest            сборка пакетов документации на компьютере
/evals                   эталонные диалоги для проверки качества
```

Важное правило: модели в репозиторий не кладём, они слишком большие. В репозитории только файл `models.yaml` со ссылками и контрольными суммами, а скрипт скачивает модели сам.

## План по этапам

Сначала всё «мозговое» отлаживаем на Mac, где итерации в разы быстрее, и только потом переносим на телефон. Каждый этап заканчивается тем, чем можно пользоваться.

1. **Подготовка.** Приватный репозиторий на GitHub, этот документ в `docs/`, первые решения в `adr/`.
   - Результат: каркас проекта.
2. **Голосовой прототип на Mac.** Python: микрофон → Whisper → Qwen → Silero TTS, ответ по предложениям, перебивание.
   - Результат: с ней можно поговорить голосом на русском и оценить задержку.
3. **Персонаж и эмоции.** Карточка в YAML, настроение дня, сиюминутные эмоции, влияние на голос.
   - Результат: у неё есть характер, и он меняется со временем.
4. **Память и проекты.** SQLite, четыре уровня памяти, ночная обработка, привязка разговоров к проектам, задачи.
   - Результат: через неделю она помнит, о чём говорили, и ведёт список задач.
5. **База знаний по лифтам.** Утилита `ingest`, описание схем через Claude, ответы со ссылками на страницы.
   - Результат: рабочие вопросы по твоим инструкциям без сети.
6. **Перенос на Android.** Kotlin-ядро, llama.cpp и whisper.cpp через JNI, перенос логики из прототипа. Пока без 3D.
   - Результат: голосовая ассистентка на S25, замер скорости и нагрева.
7. **Аватар.** Unity as a Library, VRM-персонаж, анимации, губы, мимика, команды поз.
   - Результат: она видна и двигается.
8. **Облачный шлюз.** Очередь задач, Claude API, пересказ ответов, фильтр приватных записей.
   - Результат: она передаёт сложные задачи облаку.
9. **Режимы и защита.** Расписание, переспрос при смене режима, жест «паника», нейтральная иконка.
   - Результат: полная версия 1.0.
10. **Дальше.** Синхронизация с Lift PM, слово-активатор, иврит, новые модели по мере выхода.

Этапы 2–5 — основная работа. Если они получатся хорошими, перенос на телефон и аватар — уже техника.

## Риски и открытые вопросы

| Риск | Что делаем |
| --- | --- |
| Модель на 4B слабо говорит по-русски или путается | На этапе 2 сравниваем 3–4 модели на эталонных диалогах, выбираем лучшую |
| Маленькая модель плохо раскладывает разговоры по проектам | Тяжёлую раскладку делаем ночью, длинным промптом; спорные случаи она уточняет у тебя |
| Телефон греется от модели и 3D одновременно | Замер на этапе 6; при необходимости упрощаем сцену или снижаем частоту кадров во время разговора |
| Схемы не описываются хорошо даже через Claude | Пробуем на 2–3 реальных схемах до начала этапа 5 |
| Приложение не пройдёт в Google Play | Ставим APK вручную, магазин не нужен |
